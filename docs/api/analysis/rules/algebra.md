## 4. 代数化简规则主题本身的重要性

虽然本文档当前被标记为历史说明，但“algebraic simplification” 本身依然是反编译链路中的重要主题之一。

典型代数化简规则通常会回答以下问题：

### 4.1 哪些表达式可以直接规约
例如：

- `x + 0 -> x`
- `x * 1 -> x`
- `x * 0 -> 0`
- `x & 0 -> 0`
- `x | x -> x`
- `x & x -> x`
- `x - x -> 0`
- `x ^ x -> 0`

### 4.2 哪些中间节点其实没有必要继续保留
某些表达式即使在语义上正确，如果不做局部规约，会导致：

- IR 更冗长
- 后续规则更难匹配
- 输出层产生噪音表达
- 变量恢复和类型传播压力增大

### 4.3 这些化简如何影响输出质量
代数化简不只是“让表达式更短”，它也直接影响：

- 中间表示是否更稳定
- 输出是否更接近人类可读形式
- 后续规则是否更容易继续生效
- `PrintC` 最终生成的表达式是否更自然

因此，即使这份文档当前是历史说明，**代数化简规则这个主题本身依然是当前项目的重要能力方向**。

## 7. 旧文档中典型会描述什么

按旧文档描述，这一层通常会强调或计划强调以下几类规则：

### 恒等律（Identity）
- `x + 0 -> x`
- `x * 1 -> x`

### 零化律（Nullifying）
- `x * 0 -> 0`
- `x & 0 -> 0`

### 幂等律（Idempotence）
- `x | x -> x`
- `x & x -> x`

### 抵消律（Cancellation）
- `x - x -> 0`
- `x ^ x -> 0`

这些规则在概念上都合理，也确实是规则系统常见的基础构件。  
但当前阶段应理解为：

- 它们是项目规则主题的一部分
- 它们可能在当前主线中以别的形式存在
- 它们**不能**因为旧文档存在，就自动被视为“当前已经完整实现并接入主线”
