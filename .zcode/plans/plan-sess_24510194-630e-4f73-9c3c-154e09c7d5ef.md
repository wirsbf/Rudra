# PrintC RPN 架构迁移方案

## 问题

Rudra 的 printc.rs（9171行）用直接 emit 架构（push_varnode + emit_block_ops + doc_statement），而不是 Ghidra 的 RPN 栈架构（pushOp/pushAtom/recurse）。直接 emit 导致：
- 表达式精度差（`*(long *) = ;` 空表达式、`Var1446 = op` 非法标识符）
- 无自动括号化
- 无表达式内联（implied varnode）
- goto 满天飞（78个 vs Ghidra 19个）
- 代码量是 Ghidra 的 2.7 倍但质量更差

## Ghidra RPN 流程（已确认）

```
docFunction → emitBlockGraph → emitBlockBasic →
  for each op:
    if op.output.isImplied → skip
    emitStatement(op) →
      emitExpression(op) →
        pushOp(&assignment, op)      // 推 = 到 RPN 栈
        pushSymbolDetail(output)      // 推 LHS atom
        op.getOpcode().push(this,op)  // 调度到 opCopy/opBinary 等
        recurse()                     // 排空 pending 队列
```

关键：opCopy 只是 `pushVn(op->getIn(0))`，opBinary 只是 `pushOp(tok); pushVn(in1); pushVn(in0)`。表达式重建完全由 RPN 栈自动完成。

## 已有基础设施

- ✅ `printlanguage.rs`：完整的 RPN 引擎（OpToken/ReversePolish/Atom/NodePending + rpn_push_op/rpn_push_atom/rpn_emit_op/rpn_emit_atom/rpn_recurse/rpn_op_binary/rpn_op_unary + parentheses）
- ✅ `typeop.rs`：TypeOp::push 调度已修复路由
- ✅ `prettyprint.rs`：Emit trait（print/tag_op/tag_variable/spaces/open_paren/close_paren/tag_line/begin_statement/end_statement）

## 迁移方案（渐进式，保持测试通过）

### 阶段 1：PrintC 持有 RPN 状态（核心基础设施）

在 PrintC struct 中添加 RPN 栈状态字段：
```rust
revpol: Vec<ReversePolish>,     // RPN 运算符栈
nodepend: Vec<NodePending>,      // 待处理 varnode 队列
pending: usize,                  // 已声明的 pending 数
```

实现 PrintC 上的方法（委托到 printlanguage.rs 的自由函数）：
- `push_op(tok_index, op_index)` — 委托 rpn_push_op
- `push_atom(atom)` — 委托 rpn_push_atom
- `push_vn(vn, op, mods)` — 推入 nodepend
- `recurse()` — 委托 rpn_recurse
- `clear_rpn()` — 清空栈

### 阶段 2：重写 op* 方法使用 RPN

将 printc.rs 中每个 op* 方法从直接 emit 改为 RPN push：

```rust
// 之前（直接 emit）：
fn op_copy(&mut self, op: &PcodeOp) {
    self.push_varnode(&out, Some(op));  // 直接打印
    self.emit.tag_op(" = ");
    self.push_varnode(&in0, Some(op));  // 直接打印
}

// 之后（RPN）：
fn op_copy(&mut self, op: &PcodeOp) {
    // Ghidra: pushVn(op->getIn(0), op, mods)
    if let Some(in0) = op.get_in(0) {
        self.push_vn(in0, op, 0);  // 推入 nodepend
    }
}
```

需要重写的 op* 方法（按 Ghidra printc.cc 顺序）：
- op_copy → pushVn(in0)
- op_binary → pushOp(tok); pushVn(in1); pushVn(in0)
- op_unary → pushOp(tok); pushVn(in0)
- op_load → pushOp(dereference); pushVn(in1)
- op_store → pushOp(assignment); pushOp(dereference); pushVn(addr); pushVn(value)
- op_call → pushOp(function_call); pushAtom(funcname); for each arg: pushVn(arg)
- op_return → pushAtom(return); pushVn(in0) (if exists)
- op_cbranch → pushOp逻辑 (由块结构处理)
- op_int_equal/less/add/sub/mult/... → op_binary（通过 typeop 路由）
- op_ptrsub → 结构字段访问逻辑
- op_subpiece → 截断逻辑
- op_cast → 类型转换逻辑

### 阶段 3：重写 emitExpression + emitStatement

```rust
fn emit_expression(&mut self, op: &PcodeOp) {
    // Ghidra printc.cc:2468
    if let Some(out) = op.get_out() {
        self.push_op(ASSIGNMENT_TOKEN, op_index);
        self.push_symbol_detail(&out, op, false);  // LHS atom
    }
    // 调度到 op* 方法
    TypeOpManager::push_op(self, op, None);
    self.recurse();
}

fn emit_statement(&mut self, op: &PcodeOp) {
    self.emit.begin_statement();
    self.emit_expression(op);
    self.emit.end_statement();
    if !self.is_set(COMMA_SEPARATE) {
        self.emit.print(";");
    }
}
```

### 阶段 4：重写 emitBlockBasic

```rust
fn emit_block_basic(&mut self, bb: &BlockBasic) {
    for op in bb.ops {
        if op.not_printed() { continue; }
        if op.is_branch() && !self.is_set(ONLY_BRANCH) { 
            if op == BRANCH { continue; }  // BRANCH 由块结构处理
        }
        if let Some(out) = op.output {
            if out.is_implied() { continue; }  // implied varnode 跳过
        }
        self.emit.tag_line(0);
        self.emit_statement(op);
    }
}
```

### 阶段 5：重写 doc_function

使用 Ghidra 的 emitBlockGraph 遍历结构化块（BlockIf/BlockWhileDo/...），而非 Rudra 的 emit_block_structured。

### 阶段 6：删除旧代码

移除直接 emit 的代码：
- push_varnode（保留简化版用于 push_symbol_detail）
- emit_block_ops（被 emit_block_basic 替代）
- emit_block_structured / emit_structured_if / emit_structured_whiledo（被 emitBlock* 替代）
- emit_condition / emit_block_condition（被 RPN 条件处理替代）
- doc_statement（被 emit_statement 替代）
- copy_map / def_map / value_def_map（RPN 不需要这些）

## 关键约束

1. **渐进式迁移**：每个阶段完成后跑差分测试（defects=0, 24/24 函数不超时）
2. **不碰其他文件**：只改 printc.rs 和 printlanguage.rs
3. **保留 Emit trait**：RPN emit_op/emit_atom 调用 Emit trait 的方法
4. **OpToken 表**：需要创建 Ghidra printc.cc:23-76 的静态 OpToken 实例（assignment, binary_plus, dereference, function_call 等）

## 预期效果

- 表达式自动括号化（parentheses）
- implied varnode 自动内联（recurse）
- 操作符优先级自动排序（OpToken precedence）
- 类型转换自动放置（CAST op → type token）
- 字段访问自动渲染（PTRSUB → ->field）
- 消除大量 goto（RPN 块结构更精确）
- 代码量从 9171 行大幅减少（Ghidra printc.cc 仅 3401 行）
